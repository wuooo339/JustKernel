## 1. 产品定义

JustKernel 是一个**单算子优化的 Agent 集群系统**。

它支持只提供完整算子规格从零生成工程，也支持导入已有工程；只有完整正确性验证通过才认定基线。之后让一组有明确分工的 Deep Agents 围绕同一个算子持续探索：

- supervisor 决定大方向；
- consultant 汇总探索信息；
- mentor 在各自方向上搜索、指挥 worker；
- optimizer 从零生成工程、修复及优化代码；
- tester 做快速测试；
- profiler 做详细性能分析。

集群共享探索数据，但严格隔离 worker 与 board；最终由 supervisor 收敛出最优算子，并产出探索报告。

**不是**：通用 Agent 平台、多队 PK 平台、官方榜单提交工具、算子编译器/仿真器本身。

## 2. 用户与任务

| 用户 | 目标 | 关键操作 |
| --- | --- | --- |
| 算子工程师/研究者 | 让集群探索出更好的算子实现 | 提供 OperatorSpec、可选基线源码、测试/ndjson 技能，启动/暂停集群，查看报告 |
| 集群操作者 | 控制预算、并发、设备与角色规模 | 配置模型、角色上限、硬件队列、停止条件 |
| 评审者 | 复核探索过程与最终选择 | 查看 board、任务树、候选版本、测试记录、报告 |
| 工具开发者 | 提供 tester/profiler 技能 | 编写 `SKILL.md` 与可选脚本，注册后端 |

核心任务：

1. 提供第 13 章 OperatorSpec，选择 GENERATE（无需基线源码）或 IMPORT，启动集群并建立经过验证的基线。
2. 让多个 mentor 并行探索不同方向，共享中间发现。
3. 让 worker 执行优化、测试、profile；结果回到 mentor。
4. 让 consultant 汇总，帮助 supervisor 调整方向。
5. 收敛出最优算子，保留所有候选的测试记录与探索报告。

## 3. 目标

| 编号 | 目标 | 可验证结果 |
| --- | --- | --- |
| **G1 角色分工** | 每类角色只做自己的事 | 角色能力矩阵/ACL 测试；worker 无法读 board |
| **G2 分层通信** | supervisor/consultant/mentor/worker 按边界通信 | 消息路由/越权测试 |
| **G3 动态规模** | 约 100 个逻辑 agent，按需增减 | 集群可在上限内启停 mentor/worker；无孤儿 |
| **G4 共享探索** | mentor 共享数据但各自方向探索 | board 读写/只读/misdirection 测试 |
| **G5 可插拔测试** | tester/profiler 由用户 skill 定义 | 替换 skill 不修改核心；首版 CANN 仿真 |
| **G6 全程留痕** | 每个候选有测试记录 zip | 记录完整性/哈希/关联测试 |
| **G7 收敛交付** | 输出最优算子 + 探索报告 | 选择规则、报告完整性测试 |
| **G8 可恢复** | 进程/agent/设备故障后可继续 | 崩溃/租约/消息重放测试 |
| **G9 可观察** | 人类能看到角色、消息、任务、候选、队列 | 面板/回放与事件一致 |

## 4. 非目标

| 编号 | 非目标 | 原因 |
| --- | --- | --- |
| N1 | 通用蜂群/多租户 Agent 平台 | 产品只服务单算子集群 |
| N2 | 多队 PK、排行榜、每日官测预算 | 不属于当前核心；可作为最终验收工具 |
| N3 | 公网 SaaS、账户/计费 | 本地/受信环境优先 |
| N4 | 恶意代码沙箱 | 候选代码在受信 Worker 执行；安全边界见 10 |
| N5 | 100 个 OS 进程 | 100 是逻辑 agent 规模；运行时用进程池 |
| N6 | 自动决定“最优”而不留证据 | 最优必须有测试记录与报告 |
| N7 | 让 worker 直接读 board | 违反角色隔离 |
| N8 | 让 consultant 指挥 mentor/worker | consultant 只对 supervisor 负责 |

## 5. 质量场景

### 5.1 角色与通信

- **QA-1**：worker 尝试读 mentor board 必须失败，且记录越权事件。
- **QA-2**：consultant 可以只读 mentor board，但不能写；只能向 supervisor 发 brief。
- **QA-3**：mentor 只能给直属 worker 下发任务；不能给别人的 worker 下发。
- **QA-4**：mentor 关闭 worker 后，该 worker 不再收到新任务；已有结果保留。

### 5.2 规模与生命周期

- **QA-5**：集群逻辑 agent 数不超过 `max_agents`（默认 100）；超限拒绝创建。
- **QA-6**：mentor 可以打开/关闭 worker；关闭后无孤儿会话、无残留硬件租约。
- **QA-7**：进程重启后，运行中的 agent 变为 `INTERRUPTED`，不自动重跑；任务可人工/mentor 重新派发。

### 5.3 测试与记录

- **QA-8**：每个提交候选安排 TEST，收敛前归档执行/未执行记录；只有完整执行 PASS 才能建立基线或参与最终 best 验证。
- **QA-9**：TestRecord zip 包含源码、任务、skill、配置、用例、环境、日志、结果、profile、哈希。
- **QA-10**：tester/profiler 的 skill 可替换；替换后新记录绑定新 skill 版本，旧记录仍可读。

### 5.4 硬件队列

- **QA-11**：同一设备同时只有一个独占租约；tester/profiler 都能看到排队状态。
- **QA-12**：worker 关闭/崩溃后核对物理执行，确认停止后清理租约；无法确认则隔离并告警，禁止过期执行与新执行重叠。

### 5.5 收敛与报告

- **QA-13**：supervisor 选择最优时，必须引用候选版本、测试记录和最终验证。
- **QA-14**：探索报告包含方向、分支、候选、失败路径、测试/profile 摘要、最终选择理由。

### 5.6 可恢复与可观察

- **QA-15**：消息至少一次投递，重复消息按 ID 幂等。
- **QA-16**：实时面板与离线回放对同一事件序列展示一致状态。

## 6. 成功指标

| 指标 | 目标 |
| --- | --- |
| 角色越权 | 0（自动测试拦截） |
| 无测试记录的候选 | 0（禁止成为最优） |
| 最优选择可追溯 | 100% |
| 测试记录 zip 完整性 | 100% 必需字段 |
| 硬件租约重复 | 0 |
| 集群启动/停止 | 无孤儿 agent/租约 |
| 约 100 agent 运行 | 稳定，资源上限可控 |
| 测试记录查找 | 按候选/方向/时间可查 |

## 7. 约束

- Python 3.13+；Deep Agents / LangGraph / LangChain。
- 角色 agent 使用 Deep Agents skills 机制。
- tester/profiler 首版基于 CANN 仿真；后续可接真机。
- 本地优先、受信环境；默认只监听 loopback。
- 多进程运行时：控制面、agent 运行时、工具/硬件服务分离。
- 所有候选测试记录保留；最终突出最优算子与报告。

## 8. 与旧产品叙事的关系

- 保留：Deep Agents、A2A 作为内部/外部消息传输、算子工程与测试工具。
- 删除：多队 lab、独立 Judge 官测主线、`aworker` 通用 swarm、团队 PK。
- 归一：包名/CLI 为 `justkernel`；旧数据只读迁移为 `LEGACY`。

## 9. 从零生成与持续迭代目标

- **G10 从零生成**：不提供 kernel 源码，也能生成可构建工程，经 tester 编译及完整正确性验证建立 baseline；缺少 oracle/输入约束则明确拒绝启动。
- **G11 反馈续接**：失败日志、误差、profile、历史尝试经不可变 TaskContext 传入下一任务；关闭旧 worker 后仍能继续。
- **G12 事件驱动**：Control 按事件持久化唤醒；去重、合并、WAIT deadline 和 watchdog 避免重复实验与无任务停滞。
- **QA-17**：首轮生成失败后，新 optimizer 仅靠反馈包修复成功，参考实现及用例不变。
- **QA-18**：重复结果和并发通知只产生一次必要的下一步任务；无增量不调用模型。
- **QA-19**：无性能目标可凭最终完整 TEST 通过交付；有性能目标必须有符合策略的 PROFILE。
- **QA-20**：中断后显式恢复，用新 Task 继续；旧执行未停止前不重新分配设备。

闭环与预算契约以 [13 章](13-generation-and-iteration-contract.md) 为准；持续迭代指基于证据继续搜索，不包含自动训练模型。
