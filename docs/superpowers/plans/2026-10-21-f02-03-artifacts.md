# F02-03 Content-Addressed Artifact Store Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`) syntax.

**Goal:** Implement a content-addressed artifact store with SHA-256 layout, atomic writes, hash verification, deduplication, and private permissions.

**Architecture:** `platform/artifacts/store.py` writes to `<root>/sha256/<ab>/<cd>/<digest>` using a temp file + fsync + `os.replace`. Reads verify size/hash; the DB stores only digest/relative ref, never absolute paths.

**Spec:** `SPEC/08-persistence-and-events.md` §4.

## Global Constraints

- Standard-library only; no ORM.
- Layout: `sha256/<digest[0:2]>/<digest[2:4]>/<digest>`.
- Atomic write; directory 0700, file 0600 on POSIX.
- Content dedupe; a corrupted existing artifact must not be treated as valid.
- Missing/corrupt reads raise stable errors.
- No absolute paths in refs; no old-code imports/tests.
