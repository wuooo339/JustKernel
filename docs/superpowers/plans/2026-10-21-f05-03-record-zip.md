# F05-03 TestRecord Zip Build, Validation, and Audit Records

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Build deterministic TestRecord zip archives, validate required files/checksums/manifest, and represent not-executed audit records without fake evidence.

**Architecture:** `testing/record_zip.py` owns the archive contract. The builder writes manifest, README, checksums, and caller-provided payloads; the validator rejects missing files, traversal names, checksum mismatches, manifest disagreements, and audit records claiming execution/PASS.

**Spec:** `SPEC/07-testing-and-profile.md` §3.

## Global Constraints

- Required zip files must exist; a missing file invalidates the record.
- `checksums.sha256` covers every file except itself; `manifest.files` excludes manifest and checksums.
- zip paths cannot be absolute or escape the archive.
- Executed PASS stays distinct from audit CANCELLED/UNKNOWN.
- Audit records are `executed=false`, `coverage=NONE`, task/job null, audit_id set.
- No secret/private absolute paths are introduced by the builder.
- No old-code imports/tests.
