# F01-08 ACL, Capability Matrix, Message Envelope Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`) syntax.

**Goal:** Implement typed channels, role/resource ACL, the role/tool capability matrix, and the message envelope with channel/type consistency.

**Architecture:** Pure modules under `src/justkernel/comm/`. ACL is enforced by pure functions; workers have no board tools in the capability table; messages are immutable and carry typed channels.

**Spec:** `SPEC/04-domain-model.md` §2, §6; `SPEC/05-agent-runtime-and-skills.md` §5; `SPEC/06-communication-and-orchestration.md` §2–3.

## Global Constraints

- Worker roles cannot read or write any board.
- Consultant reads MentorBoard but cannot write it; can write ConsultantBoard and send briefs.
- Supervisor cannot read a worker private channel.
- Mentor cannot access another mentor's worker channel.
- Hardware queue: tester/profiler read+write; supervisor/mentor read-only summary.
- Board posts are append-only (repository behavior); ACL only decides access.
- Message must match its allowed channel kind; board messages have no recipient; worker messages have a recipient.
- No old-code imports or old tests.
