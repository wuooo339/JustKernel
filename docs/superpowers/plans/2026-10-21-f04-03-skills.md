# F04-03 Skill Loading and Security Validation Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`) syntax.

**Goal:** Implement role-aware skill loading from base/builtin/user directories with frontmatter validation, allowed-tool subsets, backend registration, script gating, path-escape rejection, and secret-file rejection.

**Architecture:** `agent/skill_loader.py` defines `SkillDefinition`, `SkillLoader`, and `SkillLoadError`. It reads `SKILL.md`, parses YAML frontmatter, validates against role capability tables, and returns immutable definitions. Later roles can replace earlier same-named skills.

**Spec:** `SPEC/05-agent-runtime-and-skills.md` §6.

## Global Constraints

- Load order: base role → builtin tester/profiler → user tester/profiler; later same-name wins.
- `name`/`description` required; `metadata.role` must match the loaded role.
- `metadata.backend` must be registered.
- `allowed_tools` must be a subset of the role tool matrix.
- `SKILL.md` ≤ 10MB; path must stay under its skills root.
- User scripts require `allow_user_scripts=True`.
- Reject secret files (`.env`, `*.key`, `*.pem`) in skill directories.
- Application/domain imports only; no old-code imports/tests.

## Interfaces

```python
class SkillDefinition:  # frozen
    name: str; description: str; role: Role; backend: str; version: str
    allowed_tools: frozenset[Tool]; source_path: str; digest: Digest
    scripts: tuple[str, ...] = ()
    def to_ref(self) -> SkillRef: ...

class SkillLoader:
    def __init__(self, base_dir, builtin_dir, user_dir, *,
                 allow_user_scripts=False,
                 registered_backends=None) -> None: ...
    def load(self, role: Role) -> tuple[SkillDefinition, ...]: ...
```
