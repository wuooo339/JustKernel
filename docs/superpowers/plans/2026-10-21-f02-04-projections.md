# F02-04 Projections and Replay Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`) syntax.

**Goal:** Build event-sourced read models for the mentor board, cluster graph, candidate graph, and hardware queue, with per-projection cursors and deterministic replay.

**Architecture:** `platform/persistence/projections.py` contains pure in-memory view objects and a `ProjectionRunner`. The runner reads committed events after each view's cursor, applies them, and advances the cursor in the `projections` table. Rebuild resets views and cursors, then re-applies all events.

**Spec:** `SPEC/08-persistence-and-events.md` §5.

## Global Constraints

- Live application and full replay produce the same view state.
- Rebuilding projections never appends/changes events or triggers external effects.
- Cursors are per projection and persisted in `projections`.
- Malformed projection payloads raise a stable projection error.
- No old-code imports or old tests.
