# F06-07 Budget, Plateau and Duplicate Candidates

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Enforce an isolated final-validation reserve, account exploration rounds/plateau/consecutive failures, and detect duplicate candidate source without discarding provenance.

**Architecture:** `BudgetService` wraps `BudgetLedgerPort` and `BudgetPolicy`; exploration reservations cannot consume `final_validation_reserve`. `RoundTracker` state lives in the service; `CandidateService.find_duplicate()` compares immutable source digests within a cluster.

**Spec:** `SPEC/13-generation-and-iteration-contract.md` §7.

## Global Constraints

- Exploration cannot reserve the final-validation reserve.
- Only comparable complete rounds count toward plateau; tool failures do not.
- `plateau_rounds` consecutive non-improving comparable rounds trigger plateau.
- `max_rounds` and `max_consecutive_failures` stop new exploration.
- Duplicate source keeps both candidates but is detectable for default no-auto-experiment decisions.
- No old-code imports/tests.
