# F04-05 Tool Registry and Object ACL Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Implement a tool registry that exposes only role-allowed tools and enforces object-level grants before invoking a handler.

**Architecture:** `application/tool_registry.py` composes `comm.capabilities` with a `ToolContext` containing task-scoped grants. Board access remains governed by the capability matrix; worker roles cannot see board tools. Object reads/writes require matching IDs in the context grants.

**Spec:** `SPEC/05-agent-runtime-and-skills.md` §5; `SPEC/04-domain-model.md` §2.2.

## Global Constraints

- Registry `available(role)` is exactly the capability matrix.
- Worker roles have no board tools.
- A missing grant denies the object read.
- `invoke` authorizes before calling a handler; denied calls never execute handlers.
- Missing handlers raise a stable error.
- No old-code imports/tests.

## Interfaces

```python
class ObjectKind(StrEnum): CANDIDATE; TASK; CONTEXT; ARTIFACT; TEST_RECORD; TOOL_JOB; BOARD
class ObjectRef: kind: ObjectKind; id: str
class ToolContext:
    role: Role; agent_id: AgentId; cluster_id: ClusterId
    task_id: TaskId | None
    allowed_tasks/allowed_candidates/allowed_records/allowed_tool_jobs/allowed_artifacts: frozenset[str]

class ToolRegistry:
    def register(self, tool: Tool, handler: Callable[..., object]) -> None: ...
    def available(self, role: Role) -> tuple[Tool, ...]: ...
    def authorize(self, context, tool, object_ref=None) -> None: ...
    def invoke(self, context, tool, object_ref=None, *args, **kwargs) -> object: ...
```
