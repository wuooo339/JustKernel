# F05-01 Asynchronous ToolJob Service

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Make ToolJobs explicit asynchronous executions with idempotent submit, terminal state transitions, queue/execution timeouts, owner-only reads, and no terminal overwrite.

**Architecture:** Extend `ToolJob` with lifecycle timestamps/limits and add `ToolJobView`. Extend `TestingService` with `start_job`, `timeout_job`, `cancel_job`, `interrupt_job`, `fail_job`, and owner-checked `read_tool_job`. `seal_record` only succeeds from RUNNING. Submission stays idempotent by task ID.

**Spec:** `SPEC/13-generation-and-iteration-contract.md` §5; `SPEC/07-testing-and-profile.md` §3.

## Global Constraints

- One job per Task; repeat submit with same parameters returns the same job; conflicts reject.
- State machine: `QUEUED → RUNNING → SUCCEEDED | FAILED | CANCELLED | INTERRUPTED`.
- Queue timeout starts at submit; execution timeout starts when RUNNING.
- Terminal jobs cannot be overwritten.
- Only the Task's own tester/profiler can read the job.
- Sealing a record requires a RUNNING job.
- No old-code imports/tests.
