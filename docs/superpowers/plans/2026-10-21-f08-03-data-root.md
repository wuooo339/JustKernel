# F08-03 Data Root, Permissions and Single-Service Lock

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Explicitly initialize the data-root layout with private permissions and provide an exclusive cross-process service lock.

**Architecture:** `platform/data_root.py` defines the layout, creates directories/files idempotently, and tightens permissions. `ServiceLock` uses POSIX `flock` or Windows `msvcrt.locking`; constructors create nothing.

**Spec:** `SPEC/08-persistence-and-events.md` §2; `SPEC/10-configuration-security-observability.md` §2.

## Global Constraints

- Config constructors never create directories.
- `initialize_data_root()` is explicit.
- Directories 0700; database/lock files 0600.
- Existing unsafe modes are tightened.
- One service lock per data root; second owner fails closed.
- Lock is released on context exit.
- No old-code imports/tests.
