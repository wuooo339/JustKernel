# F02-05 Global Operator Registry Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`) syntax.

**Goal:** Implement the Control-owned global `registry.db` that allows at most one active cluster per operator and idempotently releases terminal clusters.

**Architecture:** `platform/persistence/registry.py` owns the registry schema and `OperatorRegistry` adapter. A partial unique index enforces one active cluster per operator; `reserve` catches SQLite conflicts and reports a stable active-operator error. `release` is idempotent for terminal states.

**Spec:** `SPEC/08-persistence-and-events.md` §11.

## Global Constraints

- One active cluster per operator across all data roots.
- Reservation happens before journal creation; recovery can inspect active rows.
- Terminal states are `COMPLETED`, `STOPPED`, `FAILED`.
- Release is idempotent; releasing an unknown/already-terminal cluster returns False.
- Reservation key is unique and makes retries idempotent.
- No old-code imports or old tests.

```python
    cluster_id: str
    operator_id: str
    journal_ref: str
    state: str
    reservation_key: str
    created_at: int

class OperatorRegistry:
    def reserve(self, *, operator_id, cluster_id, journal_ref,
                reservation_key, now_ms, state="INITIALIZING") -> RegistryEntry: ...

```
