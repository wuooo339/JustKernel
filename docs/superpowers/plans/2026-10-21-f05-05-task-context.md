# F05-05 TaskContext and Read-only Artifact Grants

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Add an application service that creates immutable TaskContext snapshots, binds base candidates, and enforces task-scoped read-only artifact grants (digest, path scope, expiry, caller).

**Architecture:** `TaskContextService` composes `Task`, `Candidate`, `TaskContext`, `ArtifactGrant`, and `ArtifactStorePort`. The domain context remains immutable; the service validates ownership/source binding before building and before reads.

**Spec:** `SPEC/13-generation-and-iteration-contract.md` §3.

## Global Constraints

- Only the Task's mentor/worker may read its context.
- Artifact reads require matching task, digest, path scope, and unexpired grant.
- Base candidate must belong to the task cluster and match the supplied source digest.
- Empty context lists require explicit reasons (domain rule).
- Read-only: no write/delete API for context or artifacts.
- No old-code imports/tests.
