# F07-01 API Skeleton, DTOs, Error Contract and Idempotency

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox (`[ ]`).

**Goal:** Establish a versioned FastAPI skeleton with read-model DTOs, RFC7807 problem responses, stable error/status mapping, and reusable idempotency-key storage/middleware.

**Architecture:** `platform/http` owns the HTTP adapter. `dtos.py` defines immutable read models; `errors.py` maps domain error codes to `application/problem+json`; `idempotency.py` stores keyed response fingerprints; `app.py` builds health/error skeleton without importing bootstrap or exposing DB rows.

**Spec:** `SPEC/09-api-and-frontend.md` §1, §4, §9; `SPEC/11-testing-and-quality.md`.

## Global Constraints

- `/api/v1/*`; no DB rows or absolute private paths in responses.
- Problem details use `application/problem+json` with stable codes.
- Idempotency key + same body returns the cached response; different body conflicts.
- Only successful responses are cached by the middleware.
- DTOs are immutable and use string/enum values; unknown metrics stay null.
- No domain imports of FastAPI.
- No old-code imports/tests.
